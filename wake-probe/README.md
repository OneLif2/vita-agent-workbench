## Shared contract

`wake_probe_protocol.h` is the single shared header. Wire format is little-endian with compile-time size/offset checks. Exact-size reads reject short/trailing data.

- Job: `ux0:/data/INAP00018/wake-probe/job.bin`, exactly 128 bytes.
- Result: `ux0:/data/INAP00018/wake-probe/result.bin`, exactly 256 bytes.
- Identity: nonzero 32-hex nonce, uppercase 16-hex source WB run, NUL/zero-padded 1..32 ASCII `[A-Za-z0-9_-]` job ID.
- Job monotonic issue/deadline: nonzero issue <= now < deadline, deadline minus issue <=30 seconds.
- RTC tick minus system-time epoch: nonzero, within 2 seconds of the job value. This is a **diagnostic clock/reboot fence, not a cryptographic boot UUID**. RTC API failure/underflow or mismatch fails; worker repeats the check each tick. It cannot establish identity under deliberate clock tampering.
- Result always has `WP_DIAGNOSTIC_ONLY=1`. It never grants readiness, remote-open, close, update or R1 authority. Core must independently match its private pending job/source run, exact approved installed content and semantic timing/error fields. Old, partial, mismatched, orphaned or impossible public records are INCONCLUSIVE/error, not acceptance.

## One-shot flow and persistence

1. Initialize private AppUtil storage, read exact job and sample actual clocks; invalid/missing job exits without touching authority or starting BG.
2. Refuse an existing live/private arm or same nonce without replacing its storage/results. Validate any prior private records rather than treating errors as absent.
3. Re-read matching public job, durably save/read back private claim, re-read matching job again, remove job. Claim is committed before arm. Root's single pending-job/owner-PTY serialization is required; public files are not an adversarial atomic-CAS authorization mechanism. Content used for arm remains the captured/claimed exact job, never a later pathname read.
4. Save an empty private trace, then a new finite arm; public stages before BG start are main-owned. Sync/readback errors stop and preserve the first error.
5. Dynamically load optional BG module, recheck live clock/TTL/arm, call StartBgApp(1) once. Record the actual rc. No retry or invented platform success.
6. Request only `sceAppMgrLaunchAppByUri(0x20000, "psgm:play?titleid=INAP00018")`; record actual rc, commit one final private main receipt, then call sceKernelExitProcess voluntarily. A request/exit-intent record is **not proof WB returned**. Safe AUTHID/API behavior is hardware-unverified and may fail explicitly; do not silently increase privileges.
7. Worker waits at most 30*100 ms for that final matching main receipt, tolerating only its own transient commit-read state. Every retry rechecks claim/generation, active arm and clock fence. Claim/generation/clock changes are never retried. Main/worker do not concurrently write public result after successful BG start.
8. Worker ticks on actual system time at nominal 5-second intervals, checks the matching private claim and arm each time, saves/readbacks its private trace, merges main actual RCs, publishes matching public diagnostics. No catch-up/backfilled ticks. Maximum 24 ticks / <120-second arm; 24 nominal ticks cover 0..115 seconds, not a claimed 120 seconds of observation.

Private files use new versioned names under WBLC00079's own savedata: wake-probe-claim.bin, wake-probe-main.bin, wake-probe-arm.bin, wake-probe-ticks.bin and first worker error record. They do not read WB keys, R1 grants or Pair QA storage. I/O is bounded, uses no O_EXCL, synchronizes and verifies exact readback. Early init/job/active/replay rejection may simply exit without a WB return request: that is a failure/INCONCLUSIVE condition, not autonomous recovery.
